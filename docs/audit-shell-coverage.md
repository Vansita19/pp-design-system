## Priority and smallest integration plan

1. **Navigation specimen and real settings rows:** most widely repeated source shell patterns are not represented by the layout diagram or generic settings switches. One Navigation family is warranted if full reusable shell coverage is in scope; Settings can remain its existing template page.
2. **Compound form controls:** invitations, numeric range/currency and copyable values fill concrete gaps. Add variations to Form layout/Form field, with shared Select/Checkbox/Button contracts and local behavior checks.
3. **Contextual dialogs and setup composition:** extend Modal and Accordion/Card after the fields exist. Do not add a separate page per invite, API key, scheduling, decision or connector workflow.
4. **Upload/empty-state variations:** image preview and unsupported/unavailable/session states fit current File upload and Empty state families.
5. **Onboarding template last:** add only once the primitives/compositions are coherent. The animated glass artwork is screen-specific presentation and lower priority than the actual form behavior.

The user's preference to keep Data table to **Chat and Inbox** remains a constraint. Team/key schemas can be represented in management/settings compositions without adding table families. The organizer's Command-K search is its own shell control; it is not found in this PP route graph and is outside the source-coverage denominator.
